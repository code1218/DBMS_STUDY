## 강조할 것

- **챕터별 DB.** 매 수업 시작 루틴은 "해당 챕터 `setup.sql` 실행 → `SHOW DATABASES LIKE 'hanip_delivery%'`로 지난 기록 확인 → `USE hanip_deliveryNN`"입니다. 첫날 이 루틴을 확실히 잡아 두면 Ch02부터 준비 시간이 1분이면 끝납니다. 1007 에러는 "기록 보호 장치가 작동한 것"이라고 미리 알려 주세요.

- **스키마는 이미 완성되어 있다.** 기존 과정과 달리 1챕터에서 테이블을 직접 만들지 않습니다. "회사에 입사하면 DB는 이미 있다. 우리는 먼저 읽는 법을 배우고, 7챕터에서 이 구조가 왜 이렇게 생겼는지 해부한다"고 이유를 분명히 말해 주세요.
- **`USE`와 SCHEMAS 더블클릭.** 1046 에러는 첫 주 내내 나옵니다. 처음부터 습관을 들이세요.
- **`LIMIT` 습관.** "처음 보는 테이블은 LIMIT부터"는 실무에서 진짜로 중요한 습관입니다.
- **`DESC`로 확인하는 습관.** 열 이름을 추측하지 않게 합니다. 기존 과정에서 `menu_name`/`name` 혼란이 많았던 만큼, 이번 과정은 열 이름이 전 챕터에서 고정이라는 점을 강조하세요.

## 자주 나오는 질문

| 질문 | 답변 요지 |
|---|---|
| "MySQL이랑 Workbench 둘 다 깔아야 해요?" | 서버는 창고, Workbench는 창고에 지시하는 리모컨. 리모컨만 있으면 창고가 없음 |
| "왜 대문자로 써요? 소문자도 되던데" | 동작은 같음. 읽는 사람을 위한 규칙. 실무 코드 리뷰 기준 |
| "`tinyint(1)`은 뭐예요?" | MySQL의 BOOLEAN. 1=참, 0=거짓 |
| "SHOW DATABASES에 sys, mysql은 뭐예요?" | 서버가 스스로 쓰는 시스템 DB. **절대 수정·삭제하지 말 것** |
| "왜 LIMIT 5 했는데 매번 같은 5행이 나와요?" | 지금은 우연히(기본키 순서) 같을 뿐 보장이 아님. 순서가 필요하면 ORDER BY (Ch02) |

3. Workbench에서 Local instance 접속 → `SELECT VERSION();` 결과 캡처
