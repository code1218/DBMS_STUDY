## 강조할 것

1. **함수 목록을 외우게 하지 않는다.** 오늘 표에 있는 함수는 전부 공식 문서·치트시트에서 찾으면 됩니다. 기억해야 할 것은 "이런 가공이 **가능하다**"와 "NULL·단위·경계에서 틀린다"입니다.
2. **고정 기준일.** 학생이 `CURDATE()`를 쓰면 결과가 기대 결과와 달라집니다. 왜 실무에선 `CURDATE()`가 맞고 교안에선 고정값인지 설명해 주세요.
3. **NULL 3연타.** Ch02(비교) → Ch03(연산·CONCAT·CASE) → Ch04(집계). 매 챕터 "NULL이면 어떻게 되지?"를 습관적으로 묻게 합니다.
4. **경계값.** 21:00 종료 가게는 21:00에 영업 중인가? 만료일 당일은 D-0인가 만료인가? 요구사항에서 경계를 명시하는 습관이 현업 SQL 품질을 가릅니다.

## 자주 나오는 질문

| 질문 | 답변 요지 |
|---|---|
| "`SUBSTRING`이랑 `SUBSTR` 달라요?" | 같은 함수. `MID`도 같음 |
| "`IFNULL`이랑 `COALESCE` 중 뭘 써요?" | 2개면 아무거나. `COALESCE`가 표준 SQL이고 인자를 여러 개 받음. Oracle은 `NVL` |
| "`IF`는 다른 DB에도 있어요?" | MySQL 전용. 이식성이 필요하면 `CASE` |
| "요일을 한글로 못 받아요?" | `lc_time_names = 'ko_KR'` 설정 시 `DAYNAME`이 한글. 또는 `CASE DAYOFWEEK(…)` |
| "나이 계산을 `YEAR(…) - YEAR(…)`로 하면 안 돼요?" | 생일이 안 지난 사람은 1살 많게 나옴. 만 나이는 `TIMESTAMPDIFF(YEAR, …)` |

## 자주 하는 실수

| 실수 | 증상 | 대처 |
|---|---|---|
| `DATE_FORMAT(…, '%H:%M')` | `18:June` | 분은 `%i` |
| `DATEDIFF(joined_at, '2026-06-30')` | 음수 | 끝이 먼저 |
| `SUBSTRING(s, 0, 3)` | 빈 문자열 | 위치는 1부터 |
| CASE에서 `ELSE` 누락 | 일부 행 NULL | ELSE를 기본으로 쓰게 |
| `ROUND(x, 2)`로 "100원 단위" 처리 | 소수 둘째 자리 반올림 | 정수 자리는 **음수** |
