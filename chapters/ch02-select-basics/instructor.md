## 강조할 것

1. **AND/OR 괄호** — 실습 문제 5 해설처럼 "수신 거부 고객에게 문자 발송" 같은 **실제 사고**로 연결하면 기억에 오래 남습니다.
2. **DATETIME 기간 조건** — `BETWEEN`으로 6건이 빠지는 걸 직접 보여 주세요. 이 과정 전체에서 기간 조건은 `>= AND <`로 통일합니다.
3. **NULL은 비교에서 빠진다** — `NOT LIKE`로 네이버가 아닌 사람을 셌는데 30명이 안 되는 예제. Ch03(IFNULL), Ch04(COUNT), Ch06(NOT IN)에서 계속 이어지는 주제입니다.
4. **ORDER BY 없는 LIMIT은 아무 N개** — 동점 예제로 "결과가 매번 같으려면 기본키를 마지막 기준으로" 습관화.

## 자주 나오는 질문

| 질문 | 답변 요지 |
|---|---|
| "`<>`랑 `!=` 뭐가 달라요?" | 같음. `<>`가 표준 SQL. 정보처리기사도 `<>` |
| "`IN` 안에 숫자도 돼요?" | 됨. `restaurant_id IN (1, 2, 3)` |
| "`LIKE`에서 `%` 자체를 찾고 싶으면?" | `LIKE '%10\%%'` 처럼 `\`로 이스케이프. 실습에선 거의 안 씀 |
| "왜 DESC 하면 숫자가 큰 게 먼저 나와요?" | Descending = 내림차순 = 큰 값부터 |
| "한글 정렬은 어떻게 돼요?" | 가나다순. `utf8mb4_0900_ai_ci` 정렬 규칙 기준 |

## 자주 하는 실수

| 실수 | 증상 | 대처 |
|---|---|---|
| 문자열에 따옴표 누락 `WHERE category = 치킨` | 1054 Unknown column '치킨' | "따옴표가 없으면 DB는 열 이름으로 읽는다" |
| 큰따옴표 `"치킨"` | MySQL에서는 동작하지만 다른 DBMS에서 에러 | 작은따옴표로 통일 |
| `WHERE`를 `ORDER BY` 뒤에 | 1064 | 작성 순서 표 다시 보여 주기 |
| `LIMIT 5 OFFSET 5`를 "5~10번째"로 이해 | 6~10번째임 | OFFSET은 "건너뛸 개수" |
| `IS NULL`을 `= 'NULL'`로 | 0행 | `'NULL'`은 네 글자짜리 문자열 |
