## 강조할 것

1. **이상 현상이 먼저, 정의는 나중.** "2NF는 부분 함수 종속을 제거한 것"을 칠판에 먼저 쓰지 마세요. 최수아 님 등급이 두 개가 되는 화면을 본 뒤에 정의를 들으면 바로 이해합니다.
2. **함수 종속과 후보키는 업무 규칙에서 나온다.** 데이터로 반례는 찾을 수 있지만, 실습 4번의 (`customer_phone`, `used_at`)처럼 **우연히 유일한** 조합에 속기 쉽습니다. 데이터는 규칙의 반례를 찾는 도구입니다.
3. **정규화는 무손실이어야 한다.** 나누고 나서 JOIN으로 원래대로 돌아오는지 `EXCEPT`로 확인하는 습관.
4. **`unit_price`는 중복이 아니다.** 많은 학생이 "정규화 = 같은 값 제거"로 오해합니다. 값이 같아 보여도 **다른 사실**이면 중복이 아닙니다.
5. **BCNF는 "결정자 = 후보키" 한 줄.** 3NF와의 차이를 정의로 설명하면 학생이 헷갈립니다. `rider_assign`에서 "하민호 소속이 3행에 흩어져 있다"를 먼저 보여 주고, "그런데 2NF·3NF 검사에는 안 걸린다 — 검사 대상인 비주요 속성이 없으니까"로 이어 가세요. 그리고 BCNF 분해의 **대가(종속 보존 실패)**까지 반드시 시연합니다. "무조건 많이 나누면 좋다"는 오해를 여기서 끊습니다.
6. **반정규화는 이유 + 감시.** "편해서"는 이유가 아닙니다. 6-2절의 검증 쿼리처럼 어긋남을 감시할 방법까지가 반정규화입니다.

## 수업 운영 팁

- 3-3, 3-5절은 트랜잭션 안에서 실행하고 ROLLBACK합니다. 학생이 ROLLBACK을 빼먹으면 5-3절의 `ADD PRIMARY KEY`가 **1062로 실패**합니다. 오히려 좋은 교육 장면이니, 그런 학생이 있으면 화면을 공유해 "갱신 이상이 남아 있으면 정규화가 막힌다"를 보여 주세요. 복구는 setup.sql 재실행.
- Reverse Engineer 창에서 FK 선이 안 보이면 **Arrange → Autolayout**. 한글 COMMENT가 깨지면 Workbench 버전 문제이니 무시해도 됩니다.
- mermaid ERD는 GitHub에서 그림으로 보입니다. 팀 과제 제출 형식으로 추천하면 발표 준비가 빨라집니다.
- 5-4절 `EXCEPT`는 MySQL **8.0.31 이상**입니다. 학생 PC가 그보다 낮으면 `NOT EXISTS`로 바꿔 보여 주세요.

## 자주 나오는 질문

| 질문 | 답변 요지 |
|---|---|
| "정규화를 많이 할수록 좋은 건가요?" | 3NF(또는 BCNF)까지가 실무 기본. 4NF·5NF는 다치·조인 종속으로 드문 경우 |
| "JOIN이 많아지면 느리지 않아요?" | 인덱스가 있으면 PK·FK JOIN은 빠름(Ch10). 실제로 느려졌을 때 반정규화 검토 |
| "대리키(`id`)와 자연키(전화번호) 중 뭘 PK로?" | 바뀔 수 있는 값(전화·이메일·이름)은 PK로 쓰지 말 것. 자연키는 UNIQUE로 |
| "식별 관계는 언제 써요?" | 자식이 부모 없이 의미가 없고 PK가 단순할 때(답글, 연결 테이블). 아니면 비식별 + UNIQUE |
| "NoSQL은 정규화 안 하잖아요?" | 읽기 패턴에 맞춰 일부러 반정규화하는 설계. 대신 갱신 이상을 애플리케이션이 책임짐 |

## 자주 하는 실수

| 실수 | 증상 | 대처 |
|---|---|---|
| `GROUP BY menu_name`만으로 집계 | 다른 가게 같은 이름 메뉴가 합쳐짐 | 가게와 함께 묶거나 `menu_id` |
| 행 수로 주문 수를 셈 | 메뉴 줄 수가 나옴 | `COUNT(DISTINCT order_id)` |
| CTAS 후 PK를 안 검 | 중복 행이 들어가도 모름 | `ALTER TABLE … ADD PRIMARY KEY` |
| 사진을 `photo1`~`photo5` 열로 | 집계·확장 불가 | 사진 한 장 = 한 행 |
| 1:0..1 관계를 INNER JOIN으로 조회 | 답글 없는 리뷰가 사라짐 | LEFT JOIN |
| 키가 하나도 아닌 열을 2NF 위반으로 판정 | 실습 10 (라)를 2NF라고 답함 | 2NF·3NF가 검사하는 것은 **비주요 속성**뿐. 후보키를 먼저 모두 찾게 하기 |
| 3NF 분해에서 분류 코드를 메뉴 쪽에 남김 | 실습 7에서 이행 종속이 그대로 | "이 열은 **누구**의 속성인가?" — 분류는 가게의 속성 |
| 공통 열이 키가 아닌 채로 분해 | JOIN하면 행이 늘어남 (실습 9) | 공통 열이 한쪽의 PK인지 확인 |
| CTE 이름을 `lines`로 지음 | 1064 문법 에러 | `LINES`는 예약어(`LOAD DATA … LINES TERMINATED BY`). `menu_lines`처럼 바꾸기 |
| 문자열 펴기에서 `LENGTH` 사용 | 한글이 3바이트라 개수가 틀림 | `CHAR_LENGTH`(글자 수) 사용 |
