## 강조할 것

1. **GROUP BY 없는 집계는 항상 1행.** 대상이 0행이어도 1행(COUNT=0, SUM=NULL)이 나온다는 점이 Q2·실습 함정으로 이어집니다.
2. **1055를 설정으로 끄지 않는다.** 검색하면 `SET sql_mode = ''`로 끄라는 답이 많이 나옵니다. "틀린 답을 조용히 내는 쿼리를 허용하는 것"이라고 분명히 말해 주세요.
3. **WHERE는 일찍, HAVING은 집계에만.** 성능과 가독성 둘 다의 문제입니다.
4. **`SUM(CASE …)`**는 이후 Ch05(JOIN+집계), Ch06(서브쿼리), 실무 리포트 전체에서 계속 씁니다. 오늘 손에 익히는 게 목표.
5. **숫자의 해석.** 취소율은 표본이 작으면 흔들리고, 도보 기사의 배달 시간은 오토바이와 비교 대상이 아니며, 4월 취소율은 원인 분석이 필요합니다. "숫자를 뽑는 사람"이 아니라 "숫자를 설명하는 사람"이 되도록.

## 자주 나오는 질문

| 질문 | 답변 요지 |
|---|---|
| "GROUP BY에 별칭 써도 돼요?" | MySQL은 됨. Oracle 등은 안 됨. 이식성이 필요하면 식 반복 |
| "`COUNT(1)`이 `COUNT(*)`보다 빠르다던데요?" | MySQL 8에서는 동일. `COUNT(*)`가 의도가 가장 분명 |
| "`AVG` 결과에 소수가 많이 붙어요" | DECIMAL로 계산되기 때문. `ROUND(AVG(…), 1)` |
| "HAVING에 별칭 써도 돼요?" | MySQL은 됨(`HAVING delivered_count >= 50`). 교안은 이식성을 위해 집계식 사용 |
| "WITH ROLLUP 말고 합계를 붙이는 방법은?" | Ch06의 `UNION ALL`로 합계 행을 직접 붙이는 방법이 있음 |
